API chậm, em xử lý thế nào? Đọc EXPLAIN, thấy Seq Scan, thêm đúng index, đo lại.
Đọc gần 1 triệu dòng chỉ để lấy 13 dòng.
Hôm nay: Index & EXPLAIN.
Phần 1: không có index, tìm 1 khách trong 1 triệu đơn phải đọc từng dòng.
Index như mục lục cuối sách. B+Tree thấp và rộng: 1 triệu dòng chỉ 3–4 tầng.
Từ 99 ms xuống 0,26 ms: nhanh khoảng 400 lần.
Index chiếm 30 MB. B+Tree làm được =, khoảng, ORDER BY; hash index chỉ =.
Phần 2: EXPLAIN chỉ lập kế hoạch, EXPLAIN ANALYZE chạy thật và cho thời gian thực tế.
Nhìn 4 thứ: loại scan, dòng bị lọc bỏ, ước lượng so với thực tế, thời gian.
Index Cond đi trong index, Filter lọc sau khi đã lấy dòng.
Seq Scan đọc cả bảng · Index Scan · Bitmap Scan · Index Only Scan không đụng bảng.
Cẩn thận: ANALYZE chạy thật. UPDATE, DELETE hãy bọc trong BEGIN và ROLLBACK.
Phần 3: index (customer_id, created_at) sắp theo customer_id trước, rồi mới theo ngày, như danh bạ.
Theo khách, theo khách + ngày, và 5 đơn mới nhất: đều nhanh, không cần Sort.
Chỉ lọc theo ngày: vi phạm leftmost prefix, Seq Scan chậm ngang như chưa có index.
Cột = đặt trước, range hoặc sort sau. Index (a, b) thay được index (a).
Phần 4: index lưu giá trị gốc của cột. ::date → viết lại thành khoảng >= và <.
lower() cần expression index. 4242.0 ép cả cột int sang numeric: truyền đúng kiểu.
Với collation en_US, LIKE 'abc%' cũng không dùng index thường. %abc cần pg_trgm hoặc full-text.
70% bảng là PAID: Seq Scan nhanh hơn, đúng. Chỉ giá trị hiếm như REFUNDED mới dùng index.
Phần 5: index chứa đủ cột query cần thì không phải sang bảng: Index Only Scan.
Thêm cột total ngoài index thì phải đọc bảng; INCLUDE (total) thì lại Index Only Scan.
Ngay sau INSERT vẫn đọc bảng, chạy VACUUM mới ra Index Only Scan. SELECT * làm mất lợi ích.
InnoDB: bảng là B+Tree theo PK, PK nên ngắn và tăng dần. PostgreSQL: heap, index trỏ tới dòng.
Phần 6: INSERT 200.000 dòng: chỉ PK 4,2 s; thêm 3 index 10,5 s.
4 index chiếm 80 MB, nặng hơn cả bảng.
Chỉ đánh index cho query hay chạy; index khoá ngoại; CONCURRENTLY trên production.
ACID: tất cả hoặc không · thoả ràng buộc · không thấy dữ liệu dở dang · commit rồi không mất.
B+Tree: 13 dòng thay vì 1 triệu · leftmost prefix · đừng biến đổi cột · index làm ghi chậm hơn.
