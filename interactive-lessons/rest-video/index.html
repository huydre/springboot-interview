Server đã trừ tiền nhưng phản hồi bị timeout, app gửi lại. Làm sao không trừ tiền 2 lần?
Idempotency-Key: gửi lại cùng key thì server trả kết quả cũ.
Hôm nay: REST API Design.
Phần 1: URL là địa chỉ của resource, dùng danh từ. Hành động nằm ở HTTP method.
Hành động nghiệp vụ: POST .../cancel. Không đặt động từ ở đầu URL.
Safe: không đổi dữ liệu. Idempotent: gọi 1 hay N lần, trạng thái như nhau. GET, PUT, DELETE có; POST không.
PUT thay toàn bộ. PATCH chỉ sửa field gửi lên: gán giá trị thì idempotent, "tăng thêm 1" thì không.
Đừng dùng GET để đổi dữ liệu: crawler, prefetch, proxy gọi GET bất cứ lúc nào.
Phần 2: status code là hợp đồng với client. Trả 200 kèm success: false làm hỏng retry, dashboard.
Không token hoặc hết hạn: 401. Token hợp lệ nhưng không đủ quyền: 403.
Hết hạn mà trả 403: client không biết gọi refresh token, user bị kẹt.
400 sai định dạng · 422 vi phạm nghiệp vụ · 409 xung đột trạng thái · 429 vượt rate limit.
Client retry 429, 503, 504 và lỗi mạng, có backoff.
Phần 3: client sinh một key cho mỗi ý định thanh toán, gửi trong header, dùng lại khi retry.
Lần đầu 201; retry cùng key và body: 200 replayed; cùng key khác body: 422; key mới: 201.
4 lần gọi, cổng thanh toán chỉ bị gọi 2 lần.
Trùng đồng thời: PRIMARY KEY chặn request sau. Giữ 1–7 ngày. Tiền thì lưu ở DB.
Phần 4: không bao giờ trả toàn bộ collection. Filter, sort, paging qua query param.
Giới hạn size. Chỉ sort theo field cố định, đừng nối chuỗi vào SQL.
Bọc Page thành DTO riêng. Sort cột không duy nhất: thêm id làm tie-breaker.
Offset nhảy trang nhưng trang sâu chậm; keyset nhanh đều nhưng không nhảy trang.
Phần 5: version trên URL (/api/v1), dễ thấy, dễ route. Chỉ tăng version khi breaking.
An toàn: thêm field response, thêm endpoint, thêm query param tuỳ chọn.
Phá client cũ: field bắt buộc mới, xoá hay đổi tên, đổi kiểu, đổi nghĩa. Enum mới: nguy hiểm.
Thêm field mới song song, giữ field cũ. Đừng bật FAIL_ON_UNKNOWN_PROPERTIES.
Phần 6: RFC 9457 application/problem+json: type, title, status, detail, instance.
Lỗi validate mặc định không nói field nào sai: override để thêm errors.
Một advice duy nhất. Lỗi 500 trả thông điệp chung kèm traceId. Exception trong Filter không tới advice.
Phần 7: trả thẳng entity: lộ dữ liệu nhạy cảm, LazyInitializationException, N+1.
Vòng lặp JSON, đổi cột DB là đổi API, nhận entity ở request: mass assignment.
Dùng record làm DTO: request có validation, response chỉ field cần. Tắt open-in-view.
@JsonIgnore chưa đủ. DTO biến API thành hợp đồng độc lập với DB.
Idempotency-Key cho POST thanh toán · 401 khác 403 · giới hạn size · luôn dùng DTO.
