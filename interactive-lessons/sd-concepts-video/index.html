Scale order-service từ 1 lên 3 instance. Job gửi email mỗi giờ chạy mấy lần?
3 lần: instance nào cũng chạy @Scheduled. Cần lock phân tán (ShedLock) hoặc tách job ra.
Hôm nay: System Design Concepts.
Phần 1: scale dọc nâng CPU, RAM một máy. Đơn giản nhưng có trần, vẫn là một điểm chết.
Scale ngang: thêm instance sau load balancer. App phải stateless, request tự mang token (JWT).
State dùng chung ra Redis, DB. Session, cache RAM, file local sai khi nhiều instance.
LB chia tải, bỏ instance hỏng qua health check. Gateway: route, xác thực, rate limit.
Phần 2: nhiều tầng cache: browser, CDN, Caffeine trong app, Redis, buffer pool của DB.
Cache-aside: miss thì đọc DB rồi nạp lại kèm TTL. Ghi: cập nhật DB rồi xoá key.
Stampede: key nóng hết hạn, request ồ ạt vào DB. Chữa: khoá, chỉ 1 request nạp lại.
Avalanche: nhiều key hết hạn cùng lúc. Chữa: TTL cộng jitter ngẫu nhiên.
Queue: tách rời service, san tải đỉnh, response nhanh hơn. Đổi lại: eventual consistency.
Giao at-least-once: consumer phải idempotent. Message lỗi mãi thì đưa vào DLQ.
Phần 3: ghi vào primary, đọc từ replica. Primary chết thì promote một replica.
Lag: ghi xong đọc replica có thể chưa thấy. readOnly → replica. Replica ≠ backup.
Sharding: hash % N đổi chỗ gần hết dữ liệu khi thêm node; consistent hashing thì không.
CAP: mạng đứt thì chọn CP, báo lỗi (số dư) hoặc AP, trả dữ liệu cũ (lượt xem).
Chọn theo từng chức năng. C của CAP khác C của ACID.
Phần 4: microservices deploy độc lập, scale riêng service nóng, hợp nhiều team.
Giá: gọi qua mạng, không transaction chung, cần tracing. Monolith: @Transactional là xong.
Modular monolith: module theo domain, chỉ gọi nhau qua interface công khai.
Distributed monolith: chung DB, gọi dây chuyền, deploy cùng nhau. Mỗi service có DB riêng.
Tách dần theo strangler fig, bắt đầu từ module ít phụ thuộc như notification.
Phần 5: payment chậm, mỗi request giữ một thread Tomcat. Pool cạn, lỗi lan dây chuyền.
Timeout bắt buộc: theo p99 của bên kia, nhỏ hơn timeout của bên gọi mình.
Retry: backoff + jitter, chỉ thao tác idempotent. Thiếu khoá chống trùng: trừ tiền 2 lần.
Circuit breaker ở bên gọi. Lỗi vượt ngưỡng: CLOSED → OPEN, trả lỗi hoặc fallback ngay.
Hết thời gian chờ: sang HALF_OPEN, cho vài request đi thử.
Chờ đủ lượt thử rồi so tỉ lệ lỗi: dưới ngưỡng thì CLOSED, từ ngưỡng trở lên thì OPEN.
Resilience4j mặc định: Retry bọc ngoài CircuitBreaker, mỗi lần thử lại đều được đếm.
Phần 6: saga là chuỗi local transaction: tạo đơn PENDING, giữ kho, thu tiền.
Thu tiền lỗi thì chạy hành động bù: trả kho, huỷ đơn. Bù không phải rollback.
Outbox: event ghi cùng transaction; relay gửi lên Kafka; consumer vẫn idempotent.
Rate limit: 429 + Retry-After, token bucket. Nhiều instance: đếm trên Redis, Lua nguyên tử.
Logs có traceId, metrics p95/p99, traces theo dấu request. Đừng gắn tag vô hạn như userId.
Stateless · cache + queue idempotent · timeout, retry, circuit breaker · saga + outbox.
Bài tiếp: Microservices.
